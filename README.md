# Invoice Keeper

Напоминания и учёт регулярных платежей: аренда, подписки, серверы. Администратор вносит платежи,
система напоминает в Telegram за 3 дня до срока, команда отмечает оплату.

- **Backend:** Python 3.13, FastAPI, SQLAlchemy (async) + PostgreSQL, aiogram 3 (Telegram-бот), uv
- **Frontend:** TypeScript, React (SPA), Vite, Chart.js, Iconify
- **Развёртывание:** Docker Compose, nginx проксирует `/api` на backend

## Быстрый старт

```bash
cp .env.example .env        # заполните администратора, при желании — Telegram и SMTP
docker compose up -d --build
```

Панель: http://localhost:8080 (порт задаётся `PORT`), Swagger: http://localhost:8080/api/v1/docs.

При `SEED_DEMO=true` пустая база заполняется тестовыми данными: платежи в RUB/USD/EUR, просроченный
платёж, платёж «по факту», разовый платёж, категории и бюджеты. Демо-пользователи (пароль `demo1234`):
`anna@example.com`, `ivan@example.com`, `olga@example.com`. Администратор — из `.env`.

Данные хранятся в томах `db` (PostgreSQL) и `data` (чеки) и переживают перезапуск.

### Локальная разработка

```bash
docker run -d --name ik-pg -e POSTGRES_USER=invoice -e POSTGRES_PASSWORD=invoice -e POSTGRES_DB=invoice -p 5432:5432 postgres:17-alpine
cd backend && uv sync && uv run uvicorn app.main:app --reload    # http://localhost:8000
cd frontend && npm install && npm run dev                        # http://localhost:5173, /api → :8000
```

## Переменные окружения

| Переменная                                                                                       | Назначение                                                                                  |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`                                                    | Учётная запись администратора. Синхронизируется при каждом старте, через панель не меняется |
| `TIMEZONE`                                                                                       | Единый часовой пояс для сроков (по умолчанию `Europe/Moscow`)                               |

| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`                                                         | Бот и чат для напоминаний. Пустой чат — напоминания в личку администратору. Пустой токен — бот выключен |

## Как это работает

**Платёж и периоды.** Регулярный платёж (название, сумма, валюта, дата ближайшей оплаты, периодичность)
разворачивается в периоды, у каждого — своя дата и своя отметка «Оплачено / Не оплачено». Периодичность:
каждый месяц, каждые 30 дней, квартал, год, разово. Даты считаются от первой даты, поэтому платёж 31-го
числа в феврале выпадает на 28/29-е, а в марте — снова на 31-е. Если указать дату в прошлом, прошедшие
периоды создаются оплаченными (без фактической даты).

**Статусы.** Оплачено — оплата подтверждена и указана фактическая дата. Просрочка — со следующего дня после
срока (оплата в день срока — вовремя). Фактическую дату можно исправить — просрочка пересчитывается, срок
не меняется. Отмена оплаты очищает дату. Новый период не стирает прошлые оплаты.

**Цены.** Изменение суммы применяется только к неоплаченным периодам, история хранит старую цену. Для
платежей «по факту» сумму вводят в каждом периоде.

**Напоминания.** Фоновый планировщик раз в минуту ищет неоплаченные периоды, до срока которых осталось
не больше 3 дней, и отправляет сообщение в Telegram-чат и в личку ответственным с указанным Telegram ID (название, сумма, валюта, срок, ссылка на оплату,
кнопки «Оплатить» и «Открыть карточку»). Отметка об отправке хранится в периоде — повторная проверка не
создаёт дубль; оплаченный период не напоминает. Платёж, добавленный позже чем за 3 дня до срока,
напоминается сразу. Архивированный (удалённый) платёж удаляет будущие неоплаченные периоды и больше не
напоминает; история оплат сохраняется. Администратор видит архивные платежи в списке и может их
разархивировать: периоды, срок которых пришёлся на время архива, не восстанавливаются. Ответственные за платёж дополнительно получают письма (SMTP),
все пользователи — уведомления в панели. Если ответственного добавили к платежу, который уже просрочен
или по которому напоминание уже ушло, он сразу получает письмо и сообщение в личку Telegram.

**Роли.** Администратор создаёт и архивирует платежи, управляет пользователями, категориями, вебхуками,
бюджетами и видит аудит. Пользователь смотрит платежи, подтверждает и отменяет оплату, исправляет дату,
прикрепляет чеки. Ограничения проверяются в API (403), а не только скрываются в интерфейсе.

**Валюты.** RUB, USD, EUR — итоги всегда считаются отдельно по каждой валюте (`/api/v1/payments/summary`).
Курсы ЦБ РФ используются только чтобы привести графики на главной к одной шкале.

### Возможности панели

- **Главная** — расходы по месяцам и по категориям (год/квартал), ближайшие и просроченные платежи.
- **Календарь** — сетка месяца со статусами, выбор дня или диапазона протяжкой, сумма по валютам,
  экспорт в Google Calendar / ICS-ссылку (публичная лента с токеном пользователя, «все» или «мои»).
- **Платежи** — «мои» и остальные карточки, фильтры по статусу, валюте и категории, карточка платежа с
  историей периодов, чеками и комментариями, ответственными, напоминанием.
- **Бюджет** — бюджет на год и на каждый месяц по валютам, обзор использования за 12 месяцев.
- **Категории** (иконки из Iconify), **Вебхуки**, **Команда**, **Аудит** — только для администратора.
- Уведомления в панели, адаптивная вёрстка для телефона.

### Telegram-бот

`/start` или `/menu` — главное меню: «Требуют оплаты (N)» (просроченные и со сроком в ближайшие 3 дня) и
«Инвойсы». Карточка платежа: оплатить / отменить оплату, добавить чек (ответьте на сообщение бота файлом
или фото), указать сумму периода для платежей «по факту» (бот спросит её и при оплате, если суммы ещё
нет), архив чеков по месяцам. Бот должен быть добавлен в чат `TELEGRAM_CHAT_ID`.

Бот отвечает только тем, чей Telegram ID указан в карточке сотрудника на странице «Команда» (у
администратора — `TELEGRAM_ADMIN_ID`), — в личке и в чате `TELEGRAM_CHAT_ID`; остальные игнорируются.
Чтобы получать напоминания в личку, сотрудник должен один раз написать боту `/start`. Свой Telegram ID
можно узнать командой `/myid` — она отвечает всем (в группе — ещё и ID чата).

Если `PUBLIC_URL` начинается с `https://`, при старте панель регистрируется как Mini App бота — кнопка
«Панель» в меню личного чата. В Mini App вход автоматический: панель проверяет подпись данных запуска
Telegram токеном бота и входит под пользователем с этим Telegram ID; если такого нет — обычная форма входа.

### Вебхуки

События: напоминание, просрочка, оплата, отмена оплаты, новый платёж, архивация. Настраиваются метод,
заголовки, авторизация (Basic, Bearer, ключ в заголовке) и тело — шаблон Jinja2 (песочница) с переменными
`event`, `event_title`, `invoice`, `occurrence`, `actor`, `payload`. Пустой шаблон отправляет весь payload
в JSON. В панели есть предпросмотр и тестовая отправка.

## API

Все эндпоинты под префиксом `/api/v1`. Swagger — `/api/v1/docs`, спецификация — [`openapi.yaml`](openapi.yaml)
/ [`openapi.json`](openapi.json) (пересобрать: `cd backend && uv run python -m scripts.export_openapi`).

Авторизация: `POST /api/v1/auth/login` возвращает токен и ставит httpOnly-cookie; для запросов к API
передавайте `Authorization: Bearer <token>`.

| Метод         | Эндпоинт                    | Назначение                                                               |
| ------------- | --------------------------- | ------------------------------------------------------------------------ |
| POST          | `/auth/login`               | Вход по логину и паролю                                                  |
| GET           | `/auth/me`                  | Текущий пользователь                                                     |
| POST          | `/auth/logout`              | Завершение текущей сессии                                                |
| GET           | `/recurring-payments`       | Список регулярных платежей                                               |
| POST          | `/recurring-payments`       | Создание регулярного платежа (админ)                                     |
| DELETE        | `/recurring-payments/{id}`  | Прекращение платежа и напоминаний с сохранением истории (админ)          |
| GET           | `/payment-occurrences`      | Список платежей (периодов), фильтры по датам, статусу, валюте, категории |
| GET           | `/payment-occurrences/{id}` | Конкретный платёж                                                        |
| PATCH         | `/payment-occurrences/{id}` | Подтверждение / отмена оплаты, исправление фактической даты              |
| GET           | `/payments/summary`         | Итоговые суммы по валютам                                                |
| GET, POST     | `/users`                    | Пользователи / создание обычного пользователя (админ)                    |
| PATCH, DELETE | `/users/{id}`               | Изменение / удаление пользователя (админ)                                |
| GET           | `/docs`                     | Swagger-документация                                                     |

Дополнительно: `PATCH /recurring-payments/{id}`, `GET /recurring-payments/{id}/occurrences`, чеки
(`/payment-occurrences/{id}/receipt`), категории, вебхуки, бюджеты, уведомления, аудит, курсы, ICS-лента
`/calendar/{token}/{all|mine}.ics`.

Пример:

```bash
TOKEN=$(curl -s localhost:8080/api/v1/auth/login -H 'content-type: application/json' \
  -d '{"email":"admin@example.com","password":"change-me"}' | jq -r .token)
curl -s localhost:8080/api/v1/payment-occurrences?status=overdue -H "Authorization: Bearer $TOKEN"
curl -s -X PATCH localhost:8080/api/v1/payment-occurrences/42 -H "Authorization: Bearer $TOKEN" \
  -H 'content-type: application/json' -d '{"is_paid": true, "paid_at": "2026-10-24"}'
```
